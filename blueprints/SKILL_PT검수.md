# PT 검수

다 만든 발표자료를 **디자인과 문구 기준으로 다시 정리하는** 절차다. 제작 스킬이 만들면서 보는 목록과 달리, 이 스킬은 완성본을 놓고 전체를 한 번에 본다. **판정만 하고, 수정은 승인을 받은 뒤에 한다.**

검수 대상은 HTML 원본이다. PDF만 있으면 PDF를 읽되, 수정은 HTML에서 하고 다시 PDF로 변환한다.

이 파일은 `pt-deck` 스킬 폴더 안의 `review.md`다. 같은 폴더의 `profile.md`와 `guides/`를 쓴다.

## 먼저 읽을 것

1. `profile.md` — 여기서 덮은 규칙은 위반으로 잡지 않는다. 말투 보호 목록의 표현은 지적하지 않는다.
2. `guides/01_PT자료_가이드.md` 8장
3. `guides/02_디자인_가이드.md` 10장·9장·8장
4. `guides/03_글쓰기_가이드.md` 3장과 5장

검수 대상 파일을 받는다. HTML이면 소스를 읽고, **화면에서 어떻게 보이는지도 확인한다.** 줄바꿈과 여백은 소스만 보면 판정할 수 없다.

---

## 점검 순서

구조 → 화면 → 문장 순으로 본다. 문장부터 고치면 구조 문제가 가려진다.

### 1. 구조 (`guides/01`)

- [ ] 슬라이드 제목이 주제어가 아니라 완전한 주장 문장인가
- [ ] 그 주장을 시각 증거가 받치는가. 불릿 나열로 대신하지 않았는가
- [ ] 한 슬라이드에 논점이 하나인가
- [ ] 슬라이드가 배포 문서를 겸하려 하고 있지 않은가
- [ ] 강조한 수치마다 라벨과 근거가 함께 있는가
- [ ] 앞에서 나온 적 없는 수치가 결론에 갑자기 등장하지 않는가

### 2. 화면 (`guides/02`)

- [ ] 색·간격·타입이 전부 토큰에서 나왔는가. 임의 hex와 임의 px이 0건인가
- [ ] 모든 간격이 8의 배수인가 (인라인 4px 예외만)
- [ ] 폰트 패밀리가 2개 이하인가
- [ ] 본문 대비가 4.5:1 이상인가
- [ ] 9장 금지 목록에 걸리는 것이 있는가 — 그라디언트, 글래스모피즘, 이모지 아이콘, 네온, 그라디언트 텍스트, 같은 크기 3열 카드 반복, `transition: all`
- [ ] 줄바꿈이 의미 단위로 끊기는가. **렌더링 화면에서 확인했는가**
- [ ] 작은 회색 캡션으로 설명을 때운 곳이 있는가
- [ ] 안쪽 패딩이 바깥 마진을 넘지 않는가
- [ ] (8장) 이어지는 슬라이드에서 반복 요소의 좌표가 같은가. 빠르게 넘겨 튀는 요소가 없는가
- [ ] (8장) 같은 위계 요소가 한 기준선에 평행하고 크기가 같은가
- [ ] (8장) 본문을 카드 나열로만 채운 슬라이드가 없는가. 수치가 전부 시각화됐는가
- [ ] (8장) 본문 하단이 빈 슬라이드가 없는가
- [ ] (8장) 이미지마다 라벨이 있는가. 넘버링에 특수문자가 없는가
- [ ] PDF 페이지 수가 슬라이드 수와 같은가. 잘린 슬라이드가 없는가

### 3. 문장 (`guides/03`)

S1 패턴부터 본다. 특히 아래가 슬라이드에서 자주 걸린다.

- [ ] C-8 부정·대칭 대구가 2회 이상인가
- [ ] C-11 연결어미 뒤 쉼표가 있는가 (프로파일에 "원래 습관"으로 적혀 있으면 넘어간다)
- [ ] D-1 결산 어휘, D-2 의의 과장이 있는가
- [ ] C-5 이모지가 있는가
- [ ] E-7 경어체가 섞여 있는가
- [ ] 제목에 줄표(—)를 붙이고 설명을 이었는가
- [ ] 처음 읽는 사람이 제목만 보고 내용을 알 수 있는가

**판정 전에 `guides/03` 3-3 오탐 방지 6원칙을 먼저 읽는다.** 지표 하나만으로 판정하지 않는다. 독립된 계열 2개 이상이 동시에 걸릴 때만 문제로 잡는다.

## 리포트 양식

지적 하나당 네 줄을 채운다. **근거 없는 취향 지적은 쓰지 않는다.**

```
[위치]   4번 슬라이드 제목 / 6번 슬라이드 하단 캡션
[규칙]   guides/03 C-8 부정 대구 (S1)
[현재]   중요한 것은 기능이 아니라 흐름입니다. 속도가 아니라 방향입니다.
[제안]   기능보다 흐름이 중요합니다. 방향은 그다음 문제입니다.
```

위치는 **이미지 없이도 찾을 수 있게** 쓴다. 슬라이드 번호와 그 안의 위치를 함께 적는다.

### 요약 표

리포트 맨 위에 둔다.

| 영역 | 건수 | 등급 |
|---|---|---|
| 구조 | n건 | — |
| 화면 | n건 | — |
| 문장 | S1 n건 / S2 n건 | A~D |

문장 등급은 `guides/03` 3-2의 판정 기준을 따른다.

### 함께 적을 것

- **잘 된 점**도 1~3개 적는다. 무엇을 유지해야 할지 알아야 다음 자료가 나아진다.
- 프로파일에서 덮은 규칙 때문에 넘어간 항목이 있으면 그렇게 적는다. 사용자가 모르는 사이에 검사가 꺼져 있으면 안 된다.

## 수정

**판정 리포트를 먼저 내고, 승인을 받은 뒤에 고친다.** 리포트와 수정을 한 번에 처리하지 않는다.

수정할 때는 `guides/03` 3-10의 4대 철칙과 3-12의 5가지 검증을 적용한다.

| 검증 | 내용 |
|---|---|
| 변경률 | 30% 넘으면 경고, 50% 넘으면 중단하고 보고 |
| 목표 달성 | 지목한 패턴이 실제로 해소됐는가 |
| 대구 전멸 방지 | C-8을 전부 밀어버리지 않았는가. 없던 자리에 새로 만들지 않았는가 |
| 수치·고유명사 | 숫자와 고유명사가 원문 그대로인가 |
| 서법 보존 | 당위와 추측 표지가 단정으로 바뀌지 않았는가 |

> **표현을 지웠을 때 문장이 성립하지 않으면, 지운 것이 아니라 망친 것이다.**

## 지킬 것

- 판정과 수정을 섞지 않는다. 판정을 내고 멈춘다.
- 수정을 승인받아 고쳤으면 PDF를 다시 변환해 함께 준다.
- 소스만 보고 여백과 줄바꿈을 판정하지 않는다. 화면을 본다.
- 프로파일이 덮은 규칙을 위반으로 잡지 않는다.
- 지적할 때 자료를 만든 사람을 평가하지 않는다. 규칙과 위치와 대안만 말한다.
- 지적 건수를 채우려고 근거 없는 항목을 만들지 않는다. 깨끗하면 깨끗하다고 말한다.
