# PT 제작

**정리된 소재를 발표자료로 바꾸는** 절차다. 소재가 있어야 시작하고, **구조를 먼저 승인받고 나서 화면을 만든다.** 순서를 바꾸지 않는다. 결과물은 HTML 슬라이드와 그것을 변환한 PDF다.

이 스킬 폴더는 자기완결적이다. 아래 파일이 모두 같은 폴더에 있다.

| 파일 | 내용 |
|---|---|
| `profile.md` | 사용자 개인 설정. **이 값이 가이드의 기본값을 덮는다** |
| `guides/01_PT자료_가이드.md` | 슬라이드 구조, 배포문서 분리, 발표 문체 |
| `guides/02_디자인_가이드.md` | 여백·색·타이포·간격, 토큰, AI티 안티패턴 |
| `guides/03_글쓰기_가이드.md` | 문장 규범, 청중·경어체, AI 문체 71패턴 |

## 0단계 — 소재가 있는지 확인

이 스킬은 **소재를 슬라이드로 옮기는 변환기**다. 소재를 만들어 내는 도구가 아니다. 아래가 갖춰졌는지 먼저 본다.

| 소재 | 무엇인가 | 없으면 |
|---|---|---|
| **주제와 결론** | 이 발표로 무엇을 말하려는가, 듣는 사람이 무엇을 하기를 바라는가 | 한 문장으로 말해 달라고 한다 |
| **근거 자료** | 수치·데이터·문서·화면·사례. 결론을 받치는 것 | 파일이나 텍스트로 달라고 한다. **지어내지 않는다** |
| **범위** | 넣을 것과 뺄 것 | 주제와 근거를 보고 제안한 뒤 확인받는다 |

주제와 근거 자료 중 하나라도 없으면 **슬라이드를 만들지 않는다.** 이렇게 말하고 멈춘다.

> 발표자료로 바꿀 소재가 아직 없습니다. 무엇을 말하려는지(결론)와 그 근거가 되는 자료(수치·문서·화면)를 먼저 주시면, 그것을 슬라이드로 옮기겠습니다. 근거 자료를 정리하는 것부터 도와드릴 수도 있습니다. 그건 이 스킬이 아니라 일반 작업으로 진행합니다.

소재가 텍스트 메모, 보고서, 데이터 파일, 회의록, 기존 문서 어느 형태로 와도 된다. 받아서 읽고, 무엇이 결론이고 무엇이 근거인지 정리해 보여준 뒤 1단계로 간다.

## 1단계 — 확인

`guides/01` 1장의 3가지를 확인한다. **위 기본값에 있는 항목은 다시 묻지 않는다.** 이번 발표가 기본값과 다른 경우만 묻는다.

| 확인할 것 | 정해지는 것 |
|---|---|
| 발표 자리 | 슬라이드 밀도, 배포 문서 필요 여부 |
| 듣는 사람 | 내용 강도, 용어 수준 |
| 자리의 공식성 | 경어체 |
| 발표 시간 | 말할 분량 |
| 주제와 담을 내용 | 나머지 전부 |

0단계에서 받은 소재로 답할 수 있는 항목은 묻지 않는다. **없는 내용을 지어내지 않는다.** 소재가 부족하면 무엇이 더 필요한지 말한다.

---

## 2단계 — 주장 문장 목록 (승인 지점)

`guides/01` 2장의 주장-증거 구조를 적용한다.

슬라이드마다 **하고 싶은 말 한 문장**을 쓴다. 주제어가 아니라 완전한 문장이어야 한다.

```
1. (표지)
2. 3분기 이탈률이 12%p 올랐고, 원인의 절반이 첫 결제 실패다      | 근거: 이탈률 추이 그래프 + 원인 분해
3. 첫 결제 실패는 카드 등록 단계에서 63%가 발생한다               | 근거: 퍼널 이탈 도표
4. 카드 등록을 3단계에서 1단계로 줄이면 이탈의 40%를 막는다        | 근거: 경쟁사 비교 + 추정 계산
5. (제안과 요청)
```

각 줄에 **그 주장을 받칠 증거**를 함께 적는다. 증거가 없는 주장은 목록에서 뺀다. 시각화할 수 없는 주장은 말로 하고 슬라이드에서 내린다.

목록을 보여주고 **여기서 멈춘다.**

> 이 구조로 가면 될까요? 순서나 빠진 내용이 있으면 말씀해 주세요.
> 승인해 주시면 화면 제작에 들어가겠습니다.

**승인 없이 4단계로 가지 않는다.** 구조가 틀리면 나중에 문구와 디자인을 아무리 고쳐도 발표가 정리되지 않는다.

## 3단계 — 형식

**기본 흐름은 HTML로 만들고 PDF로 변환하는 것이다.** 사용자가 따로 말하지 않으면 이 흐름으로 간다. 최종 산출물은 PDF이고 HTML은 원본으로 함께 준다.

| 형식 | 언제 | 결과물 |
|---|---|---|
| **HTML → PDF (기본)** | 제출, 메일 첨부, 인쇄, 보고 | `.pdf` + 원본 `.html` |
| HTML만 | 화면 발표에서 브라우저로 넘길 때, 링크로 공유할 때 | `.html` 하나 |
| PPTX | 조직 양식이 PPT로 고정된 경우 | 별도 도구가 필요하다. 없으면 HTML→PDF로 만들고 안내한다 |

### HTML 슬라이드 규격

`guides/02` 8장의 레이아웃 규칙을 그대로 따른다.

```
비율: 16:9 고정
작업 기준 크기: 1280 x 720px
한 슬라이드 = 한 <section class="slide">, width 1280px / height 720px 고정
마스터 영역: guides/02 8-1 표의 좌표를 전 페이지 동일 적용
폰트: guides/02 2장 (Pretendard 기본)
```

PDF로 정확히 넘어가도록 아래를 넣는다.

```css
@page { size: 1280px 720px; margin: 0; }
html, body { margin: 0; padding: 0; }
.slide { width: 1280px; height: 720px; overflow: hidden; page-break-after: always; break-after: page; }
.slide:last-child { page-break-after: auto; }
@media print { .nav, .controls { display: none; } }
```

화면용으로는 키보드 좌우 키로 넘기고 슬라이드 번호를 보이게 한다. 전환 효과는 넣지 않는다.

### PDF 변환

사용자 환경의 크롬(또는 엣지)으로 변환한다. 별도 설치가 필요 없다.

```
Windows:  & "C:\Program Files\Google\Chrome\Application\chrome.exe" --headless --disable-gpu --no-pdf-header-footer --print-to-pdf="출력.pdf" "file:///경로/슬라이드.html"
macOS:    "/Applications/Google Chrome.app/Contents/MacOS/Google Chrome" --headless --disable-gpu --no-pdf-header-footer --print-to-pdf="출력.pdf" "file:///경로/슬라이드.html"
```

크롬이 그 경로에 없으면 엣지(`msedge.exe`)로 같은 옵션을 쓴다. 둘 다 없으면 브라우저에서 파일을 열고 인쇄 → PDF로 저장(여백 없음, 배경 그래픽 켜기)을 안내한다.

변환한 뒤 **PDF를 열어 페이지 수가 슬라이드 수와 같은지, 잘린 슬라이드가 없는지 확인한다.** 한 슬라이드가 두 페이지로 갈라졌으면 그 슬라이드의 내용이 720px를 넘은 것이다. 내용을 줄이거나 슬라이드를 나눈다.

## 4단계 — 토큰 먼저, 화면은 그다음

`guides/02` 0장의 순서를 따른다.

```
1. 색 토큰 정의     — 브랜드 색 1개 + 중성색 + 의미색 4종
2. 간격 토큰 정의   — 8의 배수
3. 타입 스케일 정의 — 한 벌만
4. 공통 블록 정의   — 제목, 본문, 카드, 표, 차트 컨테이너, 강조 수치, 출처 라인
5. 슬라이드 제작
```

위 기본값에 색·폰트·스케일이 있으면 **그 값을 쓴다.** 없으면 `guides/02` 4-3 데스크탑 프리셋을 쓴다.

토큰을 `:root`에 CSS 변수로 모아 둔다. 슬라이드 본문에 임의 hex와 임의 px을 쓰지 않는다.

### 슬라이드를 만들 때

- `guides/02` 8장을 지킨다. 이어지는 슬라이드의 반복 요소는 같은 좌표에, 같은 위계 요소는 한 기준선에 평행하게, 본문을 카드 나열로만 채우지 않고, 하단을 비우지 않는다.
- 한 슬라이드에 논점 하나만 둔다.
- 제목은 2단계에서 승인받은 주장 문장을 그대로 쓴다.
- 본문 텍스트는 최소화하고 증거를 시각화한다. 불릿 나열로 증거를 대신하지 않는다.
- 수치를 강조할 때는 라벨과 출처를 함께 둔다. 작은 회색 캡션으로 근거를 때우지 않는다.
- 발표자가 말할 내용은 슬라이드에 올리지 말고 **발표 스크립트로 따로** 뽑는다.

## 6단계 — 발표 스크립트

발표 스크립트를 따로 만든다. `guides/01` 4장에 따라 **구어로 쓴다.** 슬라이드 문장을 그대로 읽는 원고를 만들지 않는다.

```
[3번 슬라이드 — 첫 결제 실패는 카드 등록 단계에서 63%가 발생한다]
여기 퍼널을 보시면, 결제 실패가 고르게 퍼져 있는 게 아니라 한 곳에 몰려 있습니다.
카드 등록 단계입니다. 실패한 분들 열 명 중 여섯 명이 여기서 막혔습니다.
```

배포용 문서가 필요하면 슬라이드가 아니라 별도 문서로 만든다.

## 7단계 — 자가 검수

`guides/01` 8장, `guides/02` 10장, `guides/03` 5장의 체크리스트를 스스로 돌린다.

HTML 상단에 점검 결과를 주석으로 남긴다.

## 설정을 바꾸고 싶다고 할 때

## 지킬 것

- **2단계 승인 없이 화면을 만들지 않는다.**
- 없는 내용·수치·출처를 지어내지 않는다. 재료가 부족하면 부족하다고 말한다.
- 기본값 표의 값을 무시하고 가이드 기본값으로 덮지 않는다.
- 사용자가 시키지 않은 슬라이드를 추가하지 않는다. 필요해 보이면 말만 한다.
- 만드는 중간에 미리보기 창을 띄우지 않는다. 완성한 뒤에 연다.
- `guides/`에 없는 규칙은 적용하지도 지적하지도 않는다.
