# 디자인 가이드

발표 슬라이드를 화면으로 만들 때 지키는 시각 기준이다. 여백·색·타이포·간격 같은 퀄리티 기준, 토큰과 컴포넌트를 묶는 방법, AI가 만든 티를 없애는 금지 목록을 한 문서에 담았다.

**출처 검증**

- 퀄리티 기준 → Refactoring UI (Adam Wathan)
- 8pt 그리드·간격 토큰 → Atlassian Design System (공식) + Ant Design (GitHub 98K⭐)
- 타이포그래피 → Atlassian Design System + IBM Carbon (GitHub 9K⭐)
- 토큰 3단계 → Style Dictionary (Amazon) / Design Tokens W3C Community Group
- 컴포넌트 구조 → Brad Frost, Atomic Design (atomicdesign.bradfrost.com)
- 안티패턴 → ui-ux-pro-max-skill (GitHub 120K⭐) / impeccable (github.com/pbakaus/impeccable)

## 0. 적용 순서와 우선순위

작업 전에 이 문서를 읽고, 아래 순서로 판단한다.

```
1. 화면 유형을 정한다 (1장)
2. 토큰을 먼저 만든다 — 색·간격·타입 스케일 (5장, 6장)
3. 그 토큰으로만 화면을 만든다 (2~4장)
4. 슬라이드 레이아웃 규칙을 적용한다 (8장)
5. 금지 목록을 대조한다 (9장)
6. 자가 점검을 붙인다 (10장)
```

규칙이 부딪히면 위가 이긴다.

| 순위 | 기준 |
|---|---|
| 1 | 작업을 시킨 사람의 직접 지시 (이번 작업에 한해 아래를 덮는다) |
| 2 | 프로젝트에 이미 있는 디자인 토큰·디자인 시스템 |
| 3 | 이 문서 |
| 4 | 외부 스킬·플러그인 |

**외부 스킬·플러그인은 항상 최하위다.** 그라디언트 메시, 노이즈·grain 오버레이, 과장된 그림자, 그리드를 깨는 비대칭 레이아웃을 권하는 스킬이 있는데, 이 문서 9장의 금지가 이긴다.

## 1. 화면 유형을 먼저 정한다

같은 규칙을 모든 화면에 똑같이 적용하지 않는다. **이 화면에서 무엇이 성공인지**를 정하고 나서 나머지를 적용한다.

| 유형 | 보는 사람이 하는 일 | 해당 화면 | 충돌 시 우선 |
|---|---|---|---|
| **설득형** | 보고 나서 행동한다 | 랜딩 · 캠페인 · 서비스 소개 | 주목과 행동 유도 |
| **작업형** | 맡은 일을 처리한다 | 앱 화면 · 대시보드 · 관리자 · 내부 시스템 | 스캔 속도와 일관성 |
| **이해형** | 내용을 파악한다 | **발표자료** · 리포트 · 기획 문서 · 가이드 | 구조와 가독성 |

**발표자료는 이해형이다.** 표지와 마지막 제안 슬라이드에만 설득형 장치를 쓰고, 본문은 이해형으로 간다.

- 한 화면에 유형을 2개 이상 두지 않는다. 섞였다고 판단되면 **작업형으로 내린다.**
- 유형은 2~7장의 규칙을 덮어쓰지 못한다. 규칙 안에서 무엇을 먼저 적용할지 정하는 축이다.

## 2. 퀄리티를 올리는 순서

여백 → 색상 → 타이포 → 간격 → 컴포넌트 순으로 잡는다.

### 여백

- **먼저 공간을 확보하고 요소를 배치한다.** 요소를 먼저 넣고 여백을 조정하는 순서는 금지다.
- 요소 주변 여백이 부족하면 요소를 줄이지 말고 **덜어낸다.**
- 여백이 넉넉할수록 남은 요소가 중요해 보인다. 슬라이드에서 특히 크게 작동한다.

### 색상

- 브랜드 컬러 **1개**를 포인트로만 쓴다. 여러 색을 섞지 않는다.
- 강조 목적이 아니면 무채색만 쓴다.
- 색으로 위계를 주지 말고 **크기와 굵기로 위계**를 준다.
- 완전한 검정(`#000000`) 대신 약간 밝은 `#1A1A1A`를 쓴다.
- 완전한 흰색(`#FFFFFF`)을 배경 전체에 깔지 않는다. 오프화이트 계열로 간다.

### 폰트

- 자료 전체에서 폰트 패밀리 **최대 2개**. 본문용 하나에 필요하면 제목용 하나를 더한다.
- 3개 이상 섞였으면 정리 대상이다.
- 폰트 크기는 타입 스케일에서만 고른다. 임의 크기는 금지다.

| 구분 | 목록 |
|---|---|
| **한글 본문 기본** | Pretendard (무료, 가변폰트, 한글·영문 동시 지원) |
| **한글 대체** | Noto Sans KR |
| **과사용이라 피할 것** | Inter, Roboto, Space Grotesk, Montserrat, Poppins, 본문에 system-ui |
| **영문·디스플레이 후보** | Satoshi, General Sans, Instrument Serif, Geist, Cabinet Grotesk, JetBrains Mono |
| **절대 금지** | Papyrus, Comic Sans, Lobster, Brush Script |
| **크로스 플랫폼 불일치라 금지** | Apple SD Gothic Neo, 맑은 고딕 같은 시스템 폰트 지정 |

Pretendard CDN: `https://cdn.jsdelivr.net/gh/orioncactus/pretendard/dist/web/static/pretendard.css`

### 명도 대비

| 대상 | 기준 |
|---|---|
| 일반 텍스트 | 배경 대비 **4.5:1 이상** (WCAG AA) |
| 큰 텍스트 (18px 이상, 또는 Bold 14px 이상) | **3:1 이상** |
| 아이콘·버튼 테두리 같은 UI 요소 | **3:1 이상** |

발표는 프로젝터·화상회의로 투사되면서 대비가 더 떨어진다. 기준을 빠듯하게 맞추지 말고 여유를 둔다.

### 그림자

- 깊이감을 주는 용도로만, 약하게 쓴다.
- `box-shadow: 0 2px 8px rgba(0,0,0,0.06~0.1)` 범위를 넘지 않는다.
- 장식용 그림자, glow, 두꺼운 그림자는 금지다.

### 버튼과 아이콘

- 버튼 위계는 Primary(화면당 1개) → Secondary → Tertiary 순으로 두고, 같은 위계는 자료 전체에서 같은 모양을 유지한다.
- 아이콘은 **의미를 더할 때만** 쓴다. 텍스트로 충분하면 넣지 않는다.
- 아이콘 라이브러리는 1개만 고른다. 섞으면 선 굵기와 모서리 처리가 어긋난다.

## 3. 8pt 그리드

**모든 간격과 크기는 8의 배수로 잡는다.** 타이트한 인라인 간격에만 4px를 허용한다.

```
기본 스케일: 4 / 8 / 12 / 16 / 20 / 24 / 32 / 40 / 48 / 64 / 80px
```

| 토큰 | 픽셀 | 용도 |
|---|---|---|
| XS | 4px | 아이콘과 텍스트 사이, 배지 내부 |
| S | 8px | 버튼 그룹 사이, 리스트 항목 사이 |
| M | 12px | 작은 컴포넌트 내부 패딩 |
| L | 16px | 화면 좌우 마진, 카드 내부 패딩 |
| XL | 20px | 큰 컴포넌트 패딩 |
| 2XL | 24px | 섹션 안 요소 간 간격 |
| 3XL | 32px | 섹션 간 간격 |
| 4XL | 40px | 큰 섹션 간 간격 |
| 5XL | 48px | 헤더·탭바 높이 기준 |
| 6XL | 64px | 페이지 상하 여백 |
| 7XL | 80px | 주요 섹션 간 대형 간격 |

### 안쪽이 바깥쪽을 넘지 않는다

> 컴포넌트 내부 패딩 ≤ 컴포넌트 바깥 마진

카드 내부 패딩이 16px이면 카드 사이 간격은 16~24px로 둔다. 이 규칙을 어기면 요소가 한 덩어리로 보이지 않고 그룹핑이 무너진다.

### 가까운 것은 붙이고 다른 것은 띄운다

- 관련 있는 요소: 8~12px
- 구분되는 그룹: 24~32px
- 완전히 분리되는 섹션: 32px 이상에 구분선이나 배경색 변경을 더한다

## 4. 타이포그래피

### 4-1. 적용 순서

플랫폼을 먼저 판별한다. 아래 수치가 전부 갈린다.

| 플랫폼 | 해당 산출물 |
|---|---|
| **데스크탑 웹** | **발표자료**, 리포트, 대시보드, 포트폴리오, 랜딩 |
| **모바일 앱** | 앱 화면(375px 기준), 모바일 웹, 앱 프로토타입 |

그다음 순서로 스케일을 정한다.

1. 프로젝트 디자인 시스템에 타입 스케일이 있으면 **그것만 쓴다.** 아래 프리셋보다 우선한다.
2. 없으면 4-2로 프로젝트 전용 스케일을 산출한다.
3. 산출할 시간이 없는 소규모 작업이면 4-3 프리셋을 그대로 쓴다.

셋 중 하나를 택하고 **한 자료 안에서 섞지 않는다.**

### 4-2. 타입 스케일 산출법

폰트 크기를 임의로 정하지 말고 수학적 비율로 만든다. 계산은 베이스 크기 × 비율의 거듭제곱이다.

| 비율 | 이름 | 적합한 곳 |
|---|---|---|
| 1.125 | Major Second | 정보 밀도가 높은 화면 (금융, 데이터 대시보드) |
| 1.2 | Minor Third | **기본값** — 웹·앱 모두 안전 |
| 1.25 | Major Third | 여유 있는 레이아웃 (랜딩, 마케팅) |
| 1.333 | Perfect Fourth | 임팩트가 큰 디스플레이 |

**산출 예시 — 데스크탑 (base 16px, ratio 1.2)**

```
11px = 16 ÷ 1.2³   → 캡션 (최소)
13px = 16 ÷ 1.2²   → 보조 텍스트
16px = base         → 기본 본문
19px = 16 × 1.2    → 카드 제목
23px = 16 × 1.2²   → 섹션 타이틀
28px = 16 × 1.2³   → 섹션 강조
33px = 16 × 1.2⁴   → 표지·히어로
```

산출한 스케일 밖의 중간값은 쓰지 않는다. 12px 라벨만 예외로 둔다.

임의로 12/14/15/18/22px을 섞으면 작업자마다 다른 값을 쓰게 된다. 스케일을 강제하면 누가 이어받아도 같은 위계가 나온다.

### 4-3. 데스크탑 기본 프리셋

발표자료·리포트·포트폴리오에 그대로 쓸 수 있는 값이다.

| 역할 | 크기 | 굵기 | 줄간격 | 용도 |
|---|---|---|---|---|
| Display | 40~56px | 700 | 1.15 | 표지, 장 구분 슬라이드 |
| Title L | 28~33px | 700 | 1.25 | 슬라이드 제목 |
| Title M | 23~24px | 600 | 1.3 | 소제목 |
| Title S | 19~20px | 600 | 1.4 | 카드 제목, 표 제목 |
| Body L | 17~18px | 400 | 1.6 | 리드 문단 |
| Body M | 16px | 400 | 1.6 | 기본 본문 |
| Body S | 14px | 400 | 1.5 | 보조 텍스트, 표 셀 |
| Label | 12~13px | 500 | 1.4 | 태그, 범례, 축 라벨 |
| Caption | 11~12px | 400 | 1.4 | 각주, 출처 (이보다 작게 금지) |

### 4-4. 위계·자간·줄간격

- **크기와 굵기로 위계**를 만든다. 색으로 위계를 주는 것은 최소화한다.
- 같은 레벨의 텍스트는 자료 전체에서 같은 값을 쓴다.

| 굵기 | 쓰는 곳 |
|---|---|
| 700 Bold | 슬라이드 제목, 주요 헤더 |
| 600 SemiBold | 카드 제목, 섹션 헤더 |
| 500 Medium | 라벨, 칩, 버튼 텍스트 |
| 400 Regular | 본문, 보조 텍스트 |

대문자만 쓰는 표기는 11~13px 카테고리 라벨에만 허용한다. 그 외는 금지다.

| 글자 크기 | 자간 | 이유 |
|---|---|---|
| 24px 이상 | -0.02em ~ -0.03em | 큰 글자는 자간을 좁혀야 자연스럽다 |
| 14~20px | 0 | 조정하지 않는다 |
| 12px 이하 라벨 | +0.02em ~ +0.05em | 작은 글자는 넓혀야 읽힌다 |

줄간격은 제목 1.2~1.3, 본문 1.5~1.6, 라벨·캡션 1.3~1.4로 둔다. 단락 사이 간격은 줄간격의 1.5배로 잡는다.

### 4-5. 줄바꿈 제어

한 줄에 들어가는 글자 수는 한글 기준 **데스크탑 45~60자, 모바일 30~45자**가 적당하다. 데스크탑에서 60자를 넘으면 본문 컨테이너에 `max-width`를 건다.

- **문단 영역은 가로로 넓게 잡는다.** 좁은 `max-width`로 임의 줄바꿈을 유발하지 않는다.
- 줄바꿈을 브라우저 자동 래핑에 맡기지 말고, **의미 단위로 직접 `<br>`을 넣어 읽는 흐름을 설계**한다.
- **렌더링 결과로 확인한다.** 소스에서 한 줄이라고 화면에서도 한 줄은 아니다. 실제 본문 폭에서 어디서 꺾이는지 보고, 한 줄이 될 문장을 두 줄로 만들지 않는다. 필요하면 문구를 다듬어 글자 수를 맞춘다.
- 한 줄이 하나의 완결된 의미 덩어리가 되게 `<br>` 위치를 정한다.
  - 나쁜 예: "'사용자 흐름'을 / 재설계", "하나씩 / 검증하는", "우선순위를 / 다시 정했습니다"처럼 어절이나 구가 어색하게 끊기는 것
- `word-break: keep-all`은 유지하고, `text-wrap: balance/pretty`는 어색한 고아줄을 만들면 쓰지 않는다.

## 5. 색상 시스템과 토큰

### 5-1. 토큰 3단계

```
원자값 (Primitive)  →  의미 (Semantic)  →  컴포넌트 (Component)

#4A7C59            →  --color-primary  →  --btn-primary-bg
11px               →  --text-xs        →  --badge-font-size
4px                →  --space-1        →  --chip-padding-v
```

원자값만 쓰면 브랜드 컬러를 바꿀 때 전체를 고쳐야 한다. 의미 단계까지 두면 토큰 하나만 고치면 된다.

### 5-2. 팔레트 만들기

**Primary 10단계** — 브랜드 색의 Hue를 고정하고 채도와 명도만 움직인다.

```
1단계(가장 연함) ~ 6단계(Primary) ~ 10단계(가장 진함)
채도: 1단계 10% / 6단계 60% / 10단계 80%
명도: 1단계 97% / 6단계 48% / 10단계 20%
```

**의미 색상 4종**

```css
--color-error:   #EF4444;  /* 삭제, 경고, 실패 */
--color-warning: #F59E0B;  /* 주의, 확인 필요 */
--color-success: #10B981;  /* 완료, 정상 */
--color-info:    #3B82F6;  /* 안내, 중립 정보 */
```

**중성색 10단계** — 0(흰색) / 3(경계선) / 5(비활성) / 6(보조 텍스트) / 9(주요 텍스트)

### 5-3. 색을 절제한 사례

| 서비스 | Primary | 전략 |
|---|---|---|
| 토스 | #0064FF | 무채색 베이스에 Primary를 한 곳에만 집중 |
| 카카오페이 | #FEE500 | CTA 버튼 한 곳만. 나머지는 흰색과 회색 |
| 당근 | #FF6F0F | 플로팅 버튼, 탭바 활성, 강조 텍스트에 일관 적용 |

공통점은 브랜드 컬러가 한 화면에 3~5곳을 넘지 않는다는 것이다. 슬라이드도 같다.

### 5-4. 간격 토큰

```css
--space-1:  4px;   /* 아이콘과 텍스트 사이, 배지 내부 */
--space-2:  8px;   /* 칩 내부, 인라인 요소 사이 */
--space-3:  12px;  /* 인풋 내부 패딩 */
--space-4:  16px;  /* 좌우 마진, 카드 내부 패딩 — 가장 많이 쓴다 */
--space-5:  20px;  /* 섹션 안 그룹 간격 */
--space-6:  24px;  /* 섹션 간 간격 */
--space-8:  32px;  /* 대형 섹션 분리 */
--space-10: 40px;  /* 페이지 상단 여백 */
--space-12: 48px;  /* 히어로 영역 상하 */
```

## 6. 컴포넌트를 만드는 순서

**출처**: Brad Frost, Atomic Design

```
1단계: 토큰        ← 토큰 없이 컴포넌트를 만들면 나중에 전부 다시 만든다
2단계: Atoms       ← 버튼, 인풋, 아이콘, 배지
3단계: Molecules   ← 검색바(인풋+버튼), 카드(이미지+텍스트+버튼)
4단계: Organisms   ← 헤더, 필터 패널, 리스트
5단계: Templates   ← 화면 레이아웃 골격
6단계: Patterns    ← 빈 상태, 에러 상태, 로딩 상태
```

- 토큰이 끝나기 전에 컴포넌트를 시작하지 않는다.
- Atom 단계에서 상태를 먼저 정의한다. 기본 / 활성 / 비활성 / 로딩 / 에러 다섯을 모두 정한다.
- 새 컴포넌트를 만들기 전에 기존 것으로 해결되는지 먼저 확인한다.

발표자료에 필요한 최소 세트는 제목 블록, 본문 블록, 카드, 표, 차트 컨테이너, 강조 수치 블록, 출처 라인 정도다. 이 일곱을 먼저 정의하고 슬라이드를 찍어낸다.

## 7. 수치와 차트

- **숫자만 크게 띄우지 않는다.** 무슨 수치인지를 라벨로 함께 강조한다.
- 그 수치의 출처가 **화면 안에서 추적 가능**해야 한다.
- 앞에서 나온 적 없는 수치를 결론이나 요약에 처음 등장시키지 않는다.
- 근거나 보충 설명이 필요하다고 느껴질 때 **작은 회색 캡션이나 각주로 해결하지 않는다.** 본문 문구 영역 안에 녹여 쓰고, 들어갈 자리가 없으면 기존 문장을 다시 쓰거나 그 정보가 정말 필요한지부터 본다.
- 차트는 축 라벨과 단위를 반드시 넣고, 색은 계열 구분에만 쓴다. 장식용 그라디언트는 넣지 않는다.

## 8. 슬라이드 레이아웃

발표자료에만 적용하는 규칙이다. 3~7장 위에 얹는다.

**출처**: 이 장은 문헌 근거가 아니라 **발표자료를 반복해서 만들며 굳어진 제작자 관행**이다. 다른 장과 성격이 다르므로 조직 양식이 있으면 그쪽이 우선한다.

### 8-1. 화면 규격과 고정 영역

- **16:9 고정.** 작업 기준 1280×720px.
- 챕터명·제목·부제목·구분선·본문·페이지 번호는 **전 페이지 같은 자리**에 둔다. 아래는 1280×720 기준 마스터 영역이다.

| 영역 | 위치 (px) |
|---|---|
| 좌측 기준선 | x = 60 |
| 챕터명 | y = 40 |
| 슬라이드 제목 | y = 70 |
| 부제목 | y = 118 |
| 구분선 | y = 156 |
| 본문 | y = 176 ~ 668 |
| 페이지 번호 | 우하단 |

- **본문 하단을 비우지 않는다.** 내용이 적어 아래가 비면 요소 크기를 키우거나 슬라이드를 합친다. 위쪽에 몰아놓고 아래를 비워 두는 슬라이드는 미완성으로 본다.

### 8-2. 반복되는 요소는 같은 자리에 놓는다

- **같은 유형이 이어지는 슬라이드**(기능 소개 3장, 사례 3장 등)에서 이미지·텍스트 블록·카드처럼 반복되는 객체는 **좌상단 기준점을 페이지마다 같은 x·y에** 둔다. 넘길 때 요소가 튀면 안 된다.
- **한 슬라이드 안에서 같은 위계의 요소**(카드 3개, 수치 3개, 단계 4개)는 **가로 기준선 하나에 평행하게** 놓고 높이와 폭을 맞춘다. 하나만 크거나 처져 있으면 위계가 다른 것으로 읽힌다.
- 같은 역할의 버튼·칩·수치 스트립·이미지 캡션도 슬라이드 사이에서 좌표를 유지한다.
- 확인법: 연속 슬라이드를 빠르게 넘기거나 겹쳐 본다. 움직이는 것이 있으면 고친다.

### 8-3. 박스만으로 채우지 않는다

- 슬라이드 본문을 **사각 카드 나열만으로 구성하지 않는다.** 카드는 정보를 묶는 용도이지 표현 수단이 아니다.
- 한 슬라이드에는 표현 수단을 섞는다. 그래프, 표, 흐름·비교·포함 관계 도해, 실제 화면 이미지, 강조 수치 블록, 한 줄 문장 중에서 내용에 맞는 것을 고른다.
- **수치는 반드시 시각화**한다. 숫자를 카드 안에 글자로 넣는 것은 시각화가 아니다.
- 같은 크기 카드 3개가 나란히 선 슬라이드가 두 장 이상 이어지면 9장의 "동일 크기 3열 카드 반복"에 해당한다.

### 8-4. 이미지 라벨과 넘버링

- **이미지 아래에는 무슨 화면인지 라벨을 붙인다.** 이것은 식별용이지 보충 설명이 아니므로 7장의 "작은 캡션 금지"와 충돌하지 않는다. 크기는 Body S(14px) 이상으로 하고, 회색 12px 각주로 만들지 않는다.
- **넘버링에 특수문자를 쓰지 않는다.** ①②③, [1], 1) 대신 1 2 3 / a b c로 쓴다. 시각 강조가 필요하면 도형 안에 일반 숫자를 넣는다. "1순위"처럼 등급 라벨도 기호 없이 쓴다.

## 9. AI가 만든 티를 없애는 금지 목록

### 9-1. 금지를 먼저 선언한다

> 무엇을 해달라는 지시만 받으면 결과는 학습 데이터의 평균으로 수렴한다.
> **하지 말 것을 먼저 선언**해야 평범함에서 벗어난다.

- 나쁜 지시: "깔끔하고 모던한 UI"
- 좋은 지시: "보라·파랑 그라디언트 금지, 글래스모피즘 금지, Inter 폰트 금지"
- **금지 목록을 앞에 놓고** 스타일 지시를 뒤에 둔다. 순서를 뒤집으면 금지가 무시되는 비율이 올라간다.

### 9-2. 보자마자 걸리는 패턴

| 패턴 | 대신 할 것 |
|---|---|
| 보라-파랑-시안 그라디언트 배경 | 브랜드 단색 또는 오프화이트 배경 |
| 네온 악센트 컬러 | 브랜드 컬러 1개로 통일 |
| 글래스모피즘 (`backdrop-filter: blur`) | 불투명 카드에 약한 그림자 |
| 이모지를 아이콘으로 사용 | SVG 아이콘 |
| 제목·라벨을 대문자로만 표기 | 첫 글자만 대문자 |
| 같은 크기 3열 카드 반복 | 크기·비율이 다른 카드 배치 |
| 그라디언트 텍스트 | 단색 텍스트 |
| 모든 요소에 같은 모서리 반경 | 인풋 6~8px / 카드 12px / 모달 16px로 차등 |
| Inter·Roboto·Arial 기본 폰트 | 브랜드 폰트 (한글은 Pretendard) |
| `transition: all` | `transition: opacity 200ms, transform 200ms`처럼 속성 명시 |

### 9-3. 디자이너가 알아채는 패턴

| 패턴 | 대신 할 것 |
|---|---|
| 트렌드 수치에 색상 pill ("↑12.5%") | 보조색 플레인 텍스트 |
| 카드에 굵은 컬러 테두리 | 1px 연한 테두리 또는 약한 그림자 |
| Bounce·Elastic 이징 | ease-out, ease-in-out |
| 소프트 블러 그라디언트 덩어리 | 제거 |
| 두루뭉술한 버튼 문구 ("자세히 보기") | 구체적 행동 문구 |
| 빈 상태·로딩·에러 화면 없음 | 맥락에 맞는 문구와 다음 행동 제시 |
| 카드 안에 카드를 3단계로 중첩 | 계층은 여백과 크기 차이로, 컨테이너 중첩 금지 |
| 큰 숫자에 작은 라벨을 붙인 히어로 메트릭 | 일반 타이포 위계로 처리 |
| "User Name", "Lorem ipsum" 같은 가짜 데이터 | 실제 맥락의 샘플 데이터로 레이아웃 검증 |
| 배경 틴트와 좌측 컬러 라인을 함께 쓴 이중 강조 | 둘 중 하나만 |
| 통용 표기를 굳이 한글로 직역 | 직무명·고유명사는 통용 표기 유지. 반대로 섹션 제목을 영어로 쓰는 것도 금지 |

### 9-4. 구조 수준에서 걸리는 것

| 패턴 | 대신 할 것 |
|---|---|
| 터치·클릭 영역이 작음 | 최소 44px 확보 |
| 패딩이 과하게 눌림 | 3장 기준으로 여백 확보 |
| 제목 단계 건너뜀 (h1 다음 h3) | 순차적 구조 유지 |
| 좌측 컬러바로 상태 표시 | 배경색이나 아이콘으로 |
| 한 줄이 너무 길거나 짧음 | 4-5의 글자 수 기준 적용 |

### 9-5. 레이아웃과 카피

| 패턴 | 대신 할 것 |
|---|---|
| 원형 아이콘 + 3열 피처 그리드 세트 | 원형 아이콘을 빼고 열 수·비율을 다르게 |
| 전부 가운데 정렬 | 좌측 정렬 기준선을 잡고 강조 블록만 중앙 |
| 제네릭 스톡사진 표지 | 실제 화면·데이터·도해 |
| 개성 없는 8단어 헤드라인 | 고유 명사와 수치가 들어간 구체 문장 |
| 가치를 불릿으로만 나열 | 위계 있는 문단에 근거 수치를 붙여 재구성 |

### 9-6. 업종에 따라 더 조심할 것

| 업종 | 금지 | 권장 |
|---|---|---|
| 금융·뱅킹 | 보라·핑크 그라디언트 | 무채색 기반에 브랜드 컬러 1개, 수치 가독성 우선 |
| 장소 탐색·O2O | 보라·핑크 그라디언트 | 신뢰감 있는 자연색 (그린, 베이지) |
| 헬스케어 | 과도한 색상 사용 | 명도 대비 엄격 준수 |

목록에 없는 업종이면 그 업종의 관행·규제·경쟁 서비스를 먼저 확인하고 금지 항목을 정한 다음 시작한다.

## 10. 자가 점검

HTML 산출물 상단에 점검 결과를 주석으로 남긴다.

```html
<!-- 점검: 그라디언트 0 / 이모지 0 / 임의 hex 0 / 가짜 데이터 0 / 8pt 그리드 준수 -->
```

넘기기 전에 확인한다.

- [ ] 화면 유형을 정하고 시작했는가
- [ ] 색·간격·타입이 전부 토큰에서 나왔는가. 임의 hex와 임의 px이 0건인가
- [ ] 모든 간격이 8의 배수인가 (인라인 4px 예외만)
- [ ] 폰트 패밀리가 2개 이하인가
- [ ] 본문 대비가 4.5:1 이상인가
- [ ] 9장 금지 목록에 걸리는 것이 없는가
- [ ] 이어지는 슬라이드에서 반복 요소의 좌표가 같은가. 같은 위계 요소가 한 기준선에 평행한가
- [ ] 본문을 카드 나열로만 채운 슬라이드가 없는가. 수치가 전부 시각화됐는가
- [ ] 본문 하단이 비어 있는 슬라이드가 없는가
- [ ] 이미지마다 무슨 화면인지 라벨이 있는가. 넘버링에 특수문자가 없는가
- [ ] 줄바꿈을 렌더링 화면에서 확인했는가
- [ ] 강조한 수치에 라벨과 근거가 함께 있는가
- [ ] 작은 회색 캡션으로 설명을 때운 곳이 없는가
