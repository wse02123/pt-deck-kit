# 세팅 절차 — 사용자 자료를 받아 그 사람용 스킬을 만든다

이 문서는 클로드코드가 따르는 절차다. 끝나면 **사용자 PC에 `pt-deck` 스킬이 생기고**, 이 저장소 폴더 없이도 어느 프로젝트에서든 `/PT제작` `/PT검수` `/PT설정`을 쓸 수 있게 된다.

만드는 것은 아래 한 폴더와 커맨드 3개다.

```
~/.claude/skills/pt-deck/          (Windows: C:\Users\<이름>\.claude\skills\pt-deck\)
├─ SKILL.md        제작 절차 + 이 사용자의 기본값 내장
├─ review.md       검수 절차
├─ profile.md      개인 설정 전체
└─ guides/         규칙 문서 3종 사본

~/.claude/commands/PT제작.md · PT검수.md · PT설정.md
```

절차는 7단계다. 1~5는 자료를 모아 프로파일을 만들고, 6은 스킬을 생성하고, 7은 확인한다.

---

## 시작하기 전에

먼저 이렇게 안내한다. 길게 설명하지 않는다.

> 네 가지를 여쭤보겠습니다. **파일이 없으면 없는 대로 진행되니 부담 갖지 않으셔도 됩니다.** 끝나면 이 컴퓨터의 클로드코드에 발표자료 스킬이 생깁니다.
>
> 1. 어떤 발표자료를 누구에게 보여주시나요
> 2. 예전에 만드신 PT 파일이 있나요 (PDF나 PPT)
> 3. 발표자료 만들 때 본인만의 규칙이 있나요
> 4. 평소 쓰시는 말투를 알 수 있는 글이 있나요
>
> 하나씩 가겠습니다. 중간에 "건너뛸게요"라고 하시면 넘어갑니다.

**한 번에 네 가지를 모두 묻지 않는다.** 하나씩 묻고, 답을 받고, 다음으로 간다.

---

## 1단계 — 목적과 타겟

가장 중요하고, 파일 없이 질문만으로 채울 수 있다. **이 단계는 건너뛰지 않는다.**

한 번에 하나씩 묻는다. 사용자가 이미 말한 것은 다시 묻지 않는다.

1. **어떤 자리에서 쓰는 발표자료인가** — 사내 보고, 경영진 보고, 고객 제안, 투자 유치, 강의, 콘퍼런스, 과제 제출 등
2. **실제로 듣는 사람이 누구인가** — 직책과 역할. 결정 권한이 있는 사람이 포함되는지
3. **그 사람들이 이 주제를 어디까지 아는가**
4. **그 자리가 공식적·의례적인가** — 경어체가 여기서 정해진다
5. **발표 후에 자료를 배포하는가**
6. **보통 발표 시간이 얼마나 되는가**

답을 `guides/03_글쓰기_가이드.md` 2장의 청중 4분류에 매핑해 `blueprints/profile_templates/04_목적과_타겟.md` 양식으로 `my/04_목적과_타겟.md`에 쓴다.

여러 종류의 발표를 한다면 **가장 자주 하는 것 하나를 기본값으로 잡고**, 나머지는 "다른 경우"로 적어 둔다.

---

## 2단계 — 기존 PT 파일

### 파일 받는 법 안내

> 예전에 만드신 발표자료가 있으면 `my/samples/` 폴더에 넣어주세요. PDF가 가장 좋고, PPT나 이미지도 괜찮습니다. 파일 탐색기에서 폴더에 끌어다 놓으시면 됩니다.
> 여러 개여도 좋습니다. 최근 것 2~3개면 충분합니다. 넣으신 뒤에 "넣었어요"라고 알려주세요.
>
> 없으시면 건너뛰어도 됩니다.

`my/samples/` 파일 목록을 확인하고, PDF는 Read 도구로 읽는다. 분량이 많으면 표지·목차·본문 대표 3~5장·마지막 장 위주로 본다.

### 읽어낼 것

파일에서 **사실로 확인되는 것만** 적는다.

| 항목 | 무엇을 보는가 |
|---|---|
| 슬라이드 제목 방식 | 주제어인가, 완전한 문장인가 |
| 장당 정보량 | 한 장에 논점이 몇 개인가 |
| 반복 구조 | 표지·목차·간지·마무리 장의 형식이 정해져 있는가 |
| 색 | 주로 쓰는 색, 강조에 쓰는 색, 배경색 |
| 폰트 | 어떤 폰트를 몇 종 쓰는가 |
| 레이아웃 | 좌측 정렬인가 중앙 정렬인가, 여백을 얼마나 두는가 |
| 수치 표현 | 큰 숫자를 어떻게 보여주는가, 출처를 어디에 두는가 |
| 도식 | 표·차트·다이어그램 중 무엇을 주로 쓰는가 |
| 문구 길이 | 제목과 본문이 보통 몇 글자인가 |

### 판단해서 알려줄 것

읽어낸 패턴을 **그대로 따를지, 고칠지** 사용자에게 묻는다. 여기가 이 단계의 핵심이다.

- 공용 가이드와 맞는 패턴 → "이건 그대로 가져가겠습니다"
- 공용 가이드와 부딪히는 패턴 → **사실만 말하고 선택지를 준다.** 기존 자료를 평가하거나 깎아내리지 않는다.

> 기존 자료는 슬라이드 제목이 "매출 현황"처럼 주제어로 되어 있습니다. 이 키트의 가이드는 제목을 "매출이 3분기에 12% 줄었고 원인은 이탈률이다"처럼 완전한 문장으로 쓰라고 합니다. 연구 근거가 있는 방식입니다.
>
> 어느 쪽으로 할까요?
> 1. 가이드대로 문장 제목으로 바꾼다
> 2. 기존 방식을 유지한다 (조직 양식이 정해져 있는 경우)
> 3. 섞는다 — 본문은 문장 제목, 보고용 표지는 기존 방식

선택 결과를 `my/01_내_PT_패턴.md`에 적고, **2번을 고른 항목은 "공용 규칙을 덮는 항목"으로 따로 표시**한다. 양식은 `blueprints/profile_templates/01_내_PT_패턴.md`.

### 기존 자료가 없을 때

조직 양식도 없고 참고할 톤도 없다면, `references/design_systems/`의 공개 디자인 시스템 4종(Ant Design, shadcn/ui, iOS 26, Backstage) 중 하나를 기준 톤으로 고르게 할 수 있다. 각 파일의 성격은 `references/README.md`에 있다. 고르지 않으면 `guides/02`의 기본값으로 간다. 어느 쪽이든 `guides/02` 9장의 금지가 우선한다.

## 3단계 — 본인 제작 원칙

파일이 있으면 받고, 없으면 질문으로 채운다.

1. **꼭 지키는 것이 있나요** — "표지에 로고 위치 고정", "출처는 반드시 표기" 같은 것
2. **절대 하지 않는 것이 있나요** — "애니메이션 안 씀", "이모지 금지" 같은 것
3. **조직에서 정해준 양식이 있나요** — 템플릿, 색, 폰트, 표지 형식
4. **예전에 지적받은 것이 있나요** — "글씨가 작다", "장수가 많다" 같은 피드백

4번이 특히 중요하다. 지적받은 내용은 그 조직에서 실제로 통하는 기준이라 가장 먼저 반영할 것이다.

`my/02_내_제작원칙.md`에 쓴다. 양식은 `blueprints/profile_templates/02_내_제작원칙.md`. 조직 양식이 공용 가이드와 부딪히면 **조직 양식이 이긴다.** 어느 규칙을 덮었는지 기록한다.

---

## 4단계 — 말투

### 왜 받는가

`guides/03_글쓰기_가이드.md` 3-3의 원칙 3에 따른다. **같은 사람이 AI를 쓰기 전에 쓴 글이 있으면 그것이 기준선이 된다.** 기준선 없이 판정하면 사람이 쓴 글의 절반 이상이 AI로 잘못 걸린다는 실측이 있다.

사용자에게는 이 정도로만 말한다.

> 평소에 쓰시는 말투를 알면, 제가 글을 다듬을 때 원래 쓰시던 표현을 AI 문체로 착각해서 지우는 일이 없어집니다. 예전에 직접 쓰신 글이 있으면 `my/samples/` 폴더에 넣어주세요. 보고서, 메일, 블로그 글, 무엇이든 괜찮습니다. **AI 도움 없이 직접 쓰신 글**이어야 합니다.

### 읽어낼 것

| 항목 | 보는 것 |
|---|---|
| 문장 길이 | 평균과 최장 |
| 종결 | 주로 쓰는 어미, 격식 수준 |
| 쉼표 습관 | 연결어미 뒤에 쉼표를 찍는 편인가 (C-11 오판 방지) |
| 자주 쓰는 단어 | 이 사람의 표지가 되는 어휘 |
| 말버릇 | 반복되는 표현, 구어 섞기, 반문 |
| 대구 사용 | "A가 아니라 B" 형태를 원래 쓰는 사람인가 (C-8 오판 방지) |

`my/03_내_말투.md`에 쓴다. 양식은 `blueprints/profile_templates/03_내_말투.md`. 자료가 없으면 "기준선 없음"이라고만 적는다. 없는 기준선을 지어내지 않는다.

## 5단계 — 프로파일 만들기

네 파일을 요약해 `my/00_프로파일.md`를 만든다. 스킬은 이 파일 하나만 읽고도 돌아가야 한다.

```markdown
# 내 발표자료 설정

> 마지막 세팅: YYYY-MM-DD

## 한 줄 요약
(누구에게 무엇을 만드는 사람인가)

## 기본값
| 항목 | 값 |
|---|---|
| 주 청중 | |
| 경어체 | |
| 제목 방식 | |
| 본문 폰트 | |
| 강조색 | |
| 표준 분량 | |
| 배포 문서 | 필요 / 불필요 |

## 공용 가이드를 덮는 항목
| 덮는 규칙 | 원래 규칙 | 대신 적용할 것 | 이유 |
|---|---|---|---|

## 반드시 지키는 것
## 하지 않는 것
## 교정하지 않는 표현 (말투 보호 목록)

## 상세
(01~04 파일의 내용을 이어 붙인다. 스킬 폴더에는 이 파일 하나만 들어가므로 상세도 여기 담는다)
```

**비어 있는 항목은 비워 둔다.** 짐작으로 채우지 않는다. 비어 있으면 공용 가이드의 기본값이 그대로 적용된다.

프로파일을 보여주고 확인받는다. 특히 **공용 가이드를 덮는 항목**은 하나씩 짚어 준다.

> 세팅 내용입니다. 이 중에서 공용 규칙을 덮는 항목이 3개 있습니다.
> 1. 제목은 기존 방식(주제어)을 유지 — 조직 양식
> 2. 타입 스케일은 회사 템플릿 값 고정
> 3. 연결어미 뒤 쉼표는 지적하지 않음 — 원래 습관
>
> 맞습니까? 확인해 주시면 이 설정으로 스킬을 만들겠습니다.

## 6단계 — 스킬 생성

여기서 사용자 PC에 스킬을 만든다. **이 저장소 폴더와 무관하게 동작하도록 필요한 파일을 전부 복사한다.**

### 6-1. 위치 정하기

> 스킬을 어디에 둘까요?
> 1. **이 컴퓨터 전체에서 쓰기 (권장)** — 어느 폴더에서 클로드코드를 열어도 `/PT제작`이 됩니다
> 2. **이 폴더에서만 쓰기** — 이 pt-deck-kit 폴더 안에서만 됩니다

1번이면 `~/.claude/skills/pt-deck/`, 2번이면 `./.claude/skills/pt-deck/`다. 커맨드는 각각 `~/.claude/commands/`, `./.claude/commands/`에 둔다.

`~/.claude/` 폴더는 클로드코드가 설치되어 있으면 이미 있다. `skills/`나 `commands/`가 없으면 만든다.

### 6-2. 이미 있으면

`pt-deck` 폴더가 이미 있으면 덮어쓰기 전에 묻는다. 덮어쓴다고 하면 기존 폴더를 `pt-deck_backup_YYYYMMDD`로 옮겨 두고 진행한다.

### 6-3. 파일 만들기

| 만들 파일 | 원본 | 하는 일 |
|---|---|---|
| `pt-deck/guides/01~03.md` | `guides/` 3종 | 그대로 복사 |
| `pt-deck/profile.md` | `my/00_프로파일.md` | 그대로 복사 |
| `pt-deck/SKILL.md` | `blueprints/SKILL_PT제작.md` | 복사한 뒤 **"이 사용자의 기본값" 절을 profile.md 내용으로 채운다.** 기본값 표, 덮는 항목 표, 말투 보호 목록 세 곳이다. 비어 있는 항목은 "없음" 또는 "기준선 없음"으로 적는다 |
| `pt-deck/review.md` | `blueprints/SKILL_PT검수.md` | 그대로 복사 |
| `commands/PT제작.md` `PT검수.md` `PT설정.md` | `blueprints/commands/` 3종 | 그대로 복사. 2번(이 폴더에서만)을 골랐으면 파일 안의 `~/.claude/skills/pt-deck/` 경로를 `.claude/skills/pt-deck/`로 바꾼다 |

`SKILL.md`의 frontmatter(`name: pt-deck`, `description`)는 그대로 둔다. 이것이 있어야 클로드코드가 스킬로 인식한다.

### 6-4. 확인

만든 파일 목록을 보여준다.

```
~/.claude/skills/pt-deck/SKILL.md
~/.claude/skills/pt-deck/review.md
~/.claude/skills/pt-deck/profile.md
~/.claude/skills/pt-deck/guides/01_PT자료_가이드.md
~/.claude/skills/pt-deck/guides/02_디자인_가이드.md
~/.claude/skills/pt-deck/guides/03_글쓰기_가이드.md
~/.claude/commands/PT제작.md
~/.claude/commands/PT검수.md
~/.claude/commands/PT설정.md
```

`SKILL.md`의 기본값 표가 profile.md와 같은지 눈으로 대조한다.

---

## 7단계 — 마무리

> 스킬을 만들었습니다. **클로드코드를 한 번 껐다 켜면** 아래 명령이 됩니다.
>
> - `/PT제작` — 소재(결론과 근거 자료)를 주면 발표자료로 만듭니다. HTML로 만들고 PDF로 변환해 드립니다
> - `/PT검수` — 다 만든 자료의 디자인과 문구를 다시 정리합니다
> - `/PT설정` — 설정 보기·바꾸기
>
> 이 pt-deck-kit 폴더는 지워도 스킬은 남습니다. 다만 처음부터 다시 세팅하려면 이 폴더가 필요하니, 지우기보다 두는 쪽을 권합니다.
> 자료를 더 넣고 싶으면 아무 때나 `/PT설정`에서 "이 파일 읽고 반영해줘"라고 하시면 됩니다.

## 지킬 것

- **한 번에 하나씩 묻는다.** 질문을 몰아서 던지지 않는다.
- **건너뛰기를 항상 허용한다.** 자료가 없어도 세팅은 끝나야 하고 스킬은 만들어져야 한다.
- **사용자 파일을 고치거나 지우지 않는다.** 읽고 분석만 한다.
- **관찰한 것과 추측한 것을 섞지 않는다.** 파일에서 확인한 것만 사실로 적는다.
- **기존 자료를 평가하지 않는다.** 가이드와 다른 점은 사실로 말하고 선택지를 준다.
- 세팅 도중에 발표자료를 만들지 않는다. 스킬을 만들고 나서 `/PT제작`으로 넘긴다.
- 스킬 폴더 밖의 파일(이 저장소의 `guides/`, `blueprints/`)을 고치지 않는다. 사용자 것은 스킬 폴더 안에만 쓴다.
